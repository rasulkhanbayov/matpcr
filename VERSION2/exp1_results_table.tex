% Supporting notes for the manuscript text / SI, not for the table itself:
%
% - Diffraction: positive control restricted to opXRD's CNRS and HKUST
%   institution subsets; the other five institution folders (EMPA, IKFT, INT,
%   LBNL, USC) did not yield structures with usable lattice+basis metadata in
%   this sampling and were excluded, not silently dropped.
% - Diffraction false positives in the Half-B audit were predominantly a
%   tolerance effect: 16 of 23 disagreed cases fell within 1.0 degree of a
%   real reference peak, many within 0.5-0.7 degrees, just outside the 0.5
%   degree tolerance used -- consistent with the tolerance being tighter than
%   a reasonable human read of a plotted peak position, not a broken oracle.
% - Spectrum false positives were a different, more substantive gap: only 5
%   of 28 disagreed cases were near the oracle's 5%-of-global-range
%   prominence threshold; the remaining 23 had low or negative computed
%   prominence at the human-judged peak position. This suggests the
%   prominence criterion itself may not match human judgement of "a peak is
%   present" for noisy, baseline-drifting real Raman spectra, and is flagged
%   for revisiting rather than treated as resolved by the gate decision.
% - The precision values for XRD/SEM/spectrum were judged sufficient to
%   proceed past the gate by the team (no fixed threshold is specified by
%   design); this is a recorded decision, not evidence that the oracles are
%   error-free.
% - Target property for the sign/magnitude oracle: total magnetization,
%   chosen for 100% coverage in Materials Project and a real, balanced sign
%   split (unlike formation energy, which is negative in ~99.6% of a random
%   sample and would barely test sign at all; bulk/shear modulus have ~0%
%   coverage in a random sample and would starve the audit of data).
% - A real bug in property_sign_magnitude_consistent (matpcr_metrics.py) was
%   found and fixed during Half-A: the function compared the reference value
%   to zero with exact float equality, but real DFT-computed magnetization
%   values are essentially never exactly 0.0 (numerical noise leaves values
%   like 1e-7). 82 of 3000 real materials hit this, producing false positives
%   before the fix. Fixed with an absolute-tolerance zero check
%   (zero_atol=1e-6). This was in-scope for Half-A (software correctness of
%   the oracle's own comparison logic) and did not require the co-author's
%   sign-off, which is reserved for the DFT protocol/tolerance choices
%   themselves (Half-B).
