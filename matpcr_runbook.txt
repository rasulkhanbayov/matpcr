------------------------------------------------------------------------------
 EXPERIMENT 1 -- POSITIVE CONTROL + ORACLE PRECISION AUDIT   (RUN FIRST; GATE)
------------------------------------------------------------------------------
 Objective: prove the oracles (geometric AND DFT-grounded) measure real
   violations. Inject violations at a known rate; confirm recovery. Manually
   inspect >=100 oracle-FIRED cases per oracle family; record true-violation
   fraction (precision). GATE: if precision is low, STOP and fix before anything.

------------------------------------------------------------------------------
 EXPERIMENT 2 -- MAIN EVALUATION (PCR sweep)
------------------------------------------------------------------------------
 PCR + rho_t for all models x modalities x constraint types (incl. DFT), with
 bootstrap 95% CIs and S seeds. Fills Table 1.

------------------------------------------------------------------------------
 EXPERIMENT 3 -- ACCURACY vs CONSISTENCY GAP
------------------------------------------------------------------------------
 On the labeled subset, measure accuracy and PCR on the same items; report the
 gap and the four cells. Shows PCR is not accuracy in disguise.

------------------------------------------------------------------------------
 EXPERIMENT 4 -- CGSV EFFECT
------------------------------------------------------------------------------
 PCR before vs after CGSV (Algorithm 1), same decoding, K rounds. Exact McNemar
 on discordant items; report fixes c, regressions b, p, residual violations.
 Small/insignificant is a valid, reportable outcome -- adjust framing.

------------------------------------------------------------------------------
 EXPERIMENT 5 -- VERIFIER (the released artifact)
------------------------------------------------------------------------------
 Fine-tune an open model on ORACLE labels (no human labels) to predict whether a
 chain has a violation, from input + chain alone. Report precision/recall/F1,
 ROC AUC, ECE (matpcr_metrics.py) on held-out items. Include generalization
 splits: held-out modality and held-out constraint type. Release the weights.

------------------------------------------------------------------------------
 EXPERIMENT 6 -- DETECTOR ANALYSIS
------------------------------------------------------------------------------
 Does the verifier score (or model uncertainty) predict a real violation? ROC
 AUC with bootstrap CI. Supports practical triage.

------------------------------------------------------------------------------

------------------------------------------------------------------------------
 Use the verifier to pre-filter candidate structures BEFORE DFT in ONE small

------------------------------------------------------------------------------
 FLAG-BACK TRIGGERS
------------------------------------------------------------------------------
 - Oracle precision (Exp 1) low -> fix checker/parser/DFT protocol first.
 - Models rarely expose checkable quantities -> prompt redesign.
 - PCR ~1.0 everywhere -> add harder items or narrow to benchmark+metric+verifier
   and say so honestly.
 - CGSV regressions >= fixes -> report honestly; loop is not corrective.
 - Verifier does not generalize across modality/constraint -> report the limit;
   it is still a useful in-distribution tool.
 - A neighbor appears doing DFT-grounded reasoning-chain consistency -> re-run
   novelty check and re-angle BEFORE submitting.
